# 分层式 Agent 项目管理：初步思路

维护者 2026-11-06 写的初步思路，原文照录。这是讨论的起点，不是定稿；之后的需求以 [PRD](./prd.zh.md) 为准。

---

核心思路是将 **Kanban 项目管理与 Agent Team 结合**，通过 Human、Project Manager Agent 和 Worker Agent 的分层协作，实现任务规划、分配、执行与进度管理。

## 1. Human：决策层

- 定义项目目标和需求。
- 审批任务分配，决定由哪个 Agent 执行。
- 对最终交付结果进行验收。

## 2. Project Manager Agent：管理层

- 拥有整个 Project Kanban 的全局视角，可以查看所有任务及其依赖关系。
- 负责拆解需求、规划任务、跟踪项目进度。
- 根据 Worker 的执行反馈，持续维护项目状态，提出任务调整和分配建议。
- 不直接干预 Worker 的具体执行过程。

## 3. Worker Agent：执行层

- **只能看到分配给自己的任务**，以及执行所必需的依赖信息和上下文。
- 认领 Human 已分配的任务，并独立执行。
- 自主更新任务进度、记录阻塞问题、提交执行结果和验证证据。
- 可以提出新任务建议，但不能擅自修改项目整体规划或任务分配。

## 4. 统一 Kanban：共享项目状态

所有 Agent 共享同一个 Project Task Store，但根据角色拥有不同的可见范围和操作权限。

- **PM Agent：** 全局视图，管理所有任务。
- **Worker Agent：** 局部视图，只管理自己的任务。
- **Human：** 完整视图，保留最终决策权。

Kanban 中的项目任务独立于 Agent Session 生命周期，能够长期保存任务状态、依赖关系、执行历史和交付结果。

## 核心理念

**Human 决策 → PM Agent 规划与协调 → Worker Agent 执行与反馈 → PM Agent 汇总进度 → Human 验收。**

通过分层权限和上下文隔离，让 PM Agent 专注全局协调，让 Worker Agent 专注局部任务执行，从而实现一个由人类监督、Agent 自主维护进度的项目管理与协作系统。
