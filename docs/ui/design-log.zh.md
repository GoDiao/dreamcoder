# DreamCoder 桌面 UI 设计决策与修改过程

更新日期：2026-10-17。

本记录整理自本次设计对话及其样稿，不推测每条消息的精确时间。当前仅修改演示样稿，尚未将设计应用到正式前端。Issue #91 曾在同一对话中提及，随后用户转向 UI 设计；本记录不代表该 issue 的需求或完成状态。

## 设计目标

用户认为整个应用看起来不够精致，文字大小接近，找不到重点。希望视觉感受向 Claude Code 桌面端靠齐；输入区另有 Codex 风格截图参考。

用户特别指出：不一定要采用多面板，核心问题是现在不好看。因此首要目标是清晰的文字层级、轻量的按钮与容器、紧凑的输入区和克制的常驻入口。多面板不是前提。

## 用户明确要求

| 编号 | 区域 | 要求与约束 |
| --- | --- | --- |
| U01 | 整体 | 改善视觉精致程度与信息重点，不能仅用换配色代替布局和层级调整。 |
| U02 | 文字 | 解决几乎所有文字大小一样的问题，让正文、标题、导航和辅助信息有层级。具体字号尚未逐项确认。 |
| U03 | 按钮 | 持续减轻按钮的拥挤感；不因补全功能就堆叠入口。 |
| U04 | 权限、模型菜单 | 展开后不要增加顶部标题，直接显示选项。 |
| U05 | 输入区 | 更扁、更紧凑；权限与模型控件也更窄。后续以单行输入条截图作为最新方向。 |
| U06 | 输入区结构 | 采用参考图的感觉：加号在输入条左侧、主要发送操作在右侧，项目与权限、模型信息放在输入条下方。 |
| U07 | 输入焦点 | 只有输入容器外边框即可。不要在文字编辑区域再出现橙色内框。 |
| U08 | 侧栏底部 | 将低频入口收到底部，点击菜单展开；用户曾提出「已归档 / 设置」作为例子，归档能力须先核对，见后文。 |
| U09 | 功能覆盖 | 根据现有项目功能补全样稿，不能只展示漂亮但缺少主要入口的空壳。 |
| U10 | 交付形式 | 提供独立 HTML，在旁边打开，便于选中元素提出修改。 |
| U11 | 侧栏菜单 | 不应有这么多「⋯」；明确否定「项目」分组标题旁和每个项目名旁的「⋯」。 |
| U12 | 过程留存 | 将修改细节记录在文档中，放入 UI 分支，避免丢失讨论结论；后续每轮调整同步更新记录和样稿。 |
| U13 | 顶部导航 | 顶部 tab 与侧栏会话重复，移除整条标签栏，通过侧栏切换会话。 |
| U14 | 项目行 | 右侧新建会话按钮常驻，无需 hover；图标使用 Lucide `plus`。覆盖此前悬停显示方案。 |
| U15 | 权限 | 四种 mode 的名字改为英文；展开选择时保留中文解释，仍然不加菜单标题。 |
| U16 | 会话列表 | 每行更窄、更轻，降低行高；不缩窄整个侧栏来代替压缩行高。 |
| U17 | 会话行与菜单 | 参考 Claude Code 截图，记录标题和右侧「⋯」应在同一个圆角区域内；悬停和选中背景覆盖整行，不拆成两个视觉按钮。 |
| U18 | 项目行一体化 | 项目行采用相同规则：展开箭头、项目名和常驻 plus 共用整行圆角背景，不能各自高亮。 |
| U19 | 时间信息 | 会话时间仅用于排序，不在列表显示；选择按更新时间排序时直接调整顺序，不额外展示时间。 |
| U20 | 菜单可点击性 | 会话右侧「⋯」应容易点击并稳定展开，不需要反复瞄准或点击。 |

## 当前样稿采用的方案

这些是样稿中的具体实现，不应全部视为用户已逐项批准。

| 区域 | 当前方案 | 确认状态 |
| --- | --- | --- |
| 色彩和文字 | 暖灰浅色 / 深色表面；正文约 16px，标题约 20–21px，导航约 13px，辅助信息约 11–12px。 | 样稿方案，精确数值待视觉验收。 |
| 回复 | 正文不再套厚重卡片，工具活动和思考记录可折叠、降低视觉权重。 | 样稿方案。 |
| 输入 | 默认单行，随输入增长；加号和发送位于两端。 | 按用户截图方向调整，最终尺寸待验收。 |
| 输入下方 | 左侧项目与权限，右侧模型、推理强度和上下文。 | 样稿方案。 |
| 下拉 | 权限与模型使用轻量弹出菜单，不使用原生蓝色选中列表的视觉，不添加菜单标题。 | 无标题是明确要求；其余为样稿方案。 |
| 焦点 | 移除文本框内层橙色焦点环；外层容器保留焦点反馈。 | 用户明确确认「外边框就够了」。 |
| 侧栏底部 | 去掉无明确用途的用户占位栏，保留向上展开的「更多」。 | 根据底部收纳要求采用的方案。 |
| 项目分组标题 | 保留「项目」文字与添加项目入口，移除「⋯」。 | 按用户最新反馈已修改样稿，待复看。 |
| 项目行 | 无「⋯」，右侧常驻 Lucide `plus`。展开箭头、项目名和 plus 共用整行圆角背景；悬停或键盘聚焦时统一高亮，内部按钮透明。 | 按用户最新要求修改，待复看。 |
| 会话行 | 标题单行显示，移除时间文字及悬停提示中的时间；桌面内容高约 30px，上下间隔 2px；长标题省略并提供完整提示。worktree 用分支图标表示。触摸设备点击区域至少 44px。标题与「⋯」共用整行背景，子按钮不单独填色；当前选中、悬停、聚焦、菜单展开或窄屏时显示「⋯」。 | 压缩行高和整行一体背景为明确要求；当前行显示菜单按钮参照最新截图，具体尺寸待确认。 |
| 顶部导航 | 移除标签栏及关闭、拖动标签的演示逻辑；会话由侧栏切换，草稿继续保留。设置和任务由原入口访问。终端改为展开 / 返回会话。 | 按用户明确要求修改样稿，待复看。 |
| 权限名称 | `default → Default`、`acceptEdits → Accept edits`、`plan → Plan`、`bypassPermissions → Bypass permissions`；主控件和菜单使用英文，菜单说明中文。 | 英文名称是明确要求，具体显示文案为本轮选择；保留绕过权限确认。 |
| 管理入口 | 「更多 → 项目与会话管理」，集中组织方式、排序、置顶、隐藏 / 恢复、刷新和批量管理。 | 本轮方案，用户尚未确认这一具体收纳方式。 |
| 辅助面板 | 文件与差异、终端按需打开，保持聊天区域为主。 | 样稿方案，不要求默认多面板。 |

## 修改过程

以下按对话顺序排列；后面的要求覆盖前面冲突的方案。

| 阶段 | 反馈或发现 | 修改与结果 |
| --- | --- | --- |
| 初始讨论 | 用户希望向 Claude Code 桌面 UI 看齐，并要求 wireframe。 | 制作结构线框，讨论导航、聊天区和输入区。 |
| 视觉样稿 | 用户指出整体低级感、文字大小接近、重点不明；强调并非必须多面板。 | 调整字体层级、留白、容器重量和色彩，形成视觉样稿。 |
| 按钮第一轮 | 用户认为按钮仍可调整；截图中的权限下拉呈原生菜单外观。 | 调整权限、模型等控件和弹出菜单样式。 |
| 下拉标题 | 用户明确要求权限与模型展开后不应有顶部标题。 | 删除这两类菜单的标题区。 |
| 输入区紧凑化 | 用户希望输入框更扁，初始约两行，下面权限与模型控件更窄。 | 减少输入区高度、控件尺寸和留白。 |
| 单行输入参考 | 用户提供单行圆角输入条、下方配置行的截图。 | 改为默认单行输入，配置行移到容器外，内容多时自动增高。该方向覆盖早期两行方案。 |
| 焦点边框 | 用户指出打字出现橙色内框，并确认只要外边框。 | 移除 textarea 内层焦点环，保留容器外框反馈。 |
| 侧栏底部 | 用户问用户栏的用途，建议将已归档 / 设置收到下面菜单。 | 删除用户占位栏，设置等低频入口放进底部「更多」。 |
| 功能核对 | 用户要求完整列出当前页面功能。源码核对发现没有接通的独立归档功能。 | 纠正早期样稿里的「已归档」入口；区分隐藏项目、恢复项目与删除会话。 |
| 补全样稿 | 用户要求把现有功能设计并补进样稿。 | 加入项目、会话、标签、文件、终端、任务、设置等主要入口及典型状态。此时增加过多「⋯」，随后被用户否定。 |
| 独立预览 | 用户要求导出 HTML 在旁边打开，以便选择元素微调。 | 保留源片段，导出独立 HTML。 |
| 菜单收敛 | 用户标注项目分组及项目行，指出不应有这么多「⋯」。 | 删除两处菜单；项目行只保留按需出现的新建会话按钮；低频管理集中到底部；会话菜单默认不常驻。 |
| 文档留存 | 用户担心后续忘记修改细节，要求在 UI 分支找地方记录。 | 建立本目录，将当前源片段和独立预览一并保存。 |
| 持续同步 | 用户明确要求后续调整时同步改动记录。 | 本文档及仓库样稿随每次迭代一起更新。 |
| 导航与密度 | 用户标注四处：顶部 tab 冗余；项目加号应常驻且用 Lucide plus；权限名英文、解释中文；会话行仍笨重。 | 去掉标签栏，保留侧栏切换和草稿；项目行常驻加号；四模式英文名加中文说明；会话改为标题和时间同行，降低行高。终端标签入口同步改为展开 / 返回。 |
| 会话行一体化 | 用户提供 Claude Code 记录截图，要求记录和菜单位于同一个框内。 | 悬停背景从标题按钮移到整行；标题与菜单按钮均透明，选中或菜单展开时整行统一高亮；当前选中行显示「⋯」。保留上一轮单行高度与时间信息。 |
| 项目行一体化 | 用户进一步指出项目行也应与会话行一致。 | 项目名称、展开箭头与常驻 plus 的 hover / 聚焦背景统一由项目行承载；子按钮透明，行圆角及右内边距与会话行对齐。 |
| 隐藏会话时间 | 用户指出时间用于排序即可，无需在 UI 中展示。 | 去掉会话行、标题提示和搜索结果中的时间；移除按时间分组的日期标题方案。保留创建 / 更新时间排序，用样例时间字段排序，新建及发送消息更新对应字段。保留 worktree 和执行中状态。 |
| 菜单点击修复 | 用户反馈会话右侧菜单很难点开，截图仍带时间，可能未加载最新副本。 | 隔离事件测试复现图标替换后同一次点击被外部监听误判，菜单刚打开即关闭。菜单触发器停止点击冒泡；菜单点击区域扩大为桌面 36px 宽、整行高，触摸为 44px；项目拖动仅从项目标题开始。实际浏览器原因尚未直接确认。 |

## 功能覆盖与边界

上一轮源码核对以当时工作区为依据，以下作为后续落地的入口清单；实现前仍应对照 UI 分支基线及最新代码复核。

- 项目与会话：添加项目、展开 / 收起、搜索、新建、重命名、删除、批量操作、分组、排序、置顶、隐藏 / 恢复。
- 原应用标签能力：切换、关闭、拖动排序、关闭其他标签及运行中关闭确认。最新设计明确取消顶部标签栏，不再把这些标签操作作为当前样稿的验收要求；正式实现需重新梳理其运行任务生命周期影响。
- 聊天：正文、工具与思考折叠、复制、引用、分支会话、修改摘要和撤销入口。
- 输入：附件、拖放 / 粘贴、文件引用、斜杠命令、草稿、发送 / 停止、工作目录与分支。
- 运行配置：权限、模型、服务商、推理强度、上下文使用情况。
- 运行状态：执行中、等待授权、需要用户回答、成员会话、目录不可用；目标、任务、后台活动、压缩和记忆记录。
- 工作区：变更 / 全部文件、过滤、预览、差异、引用文件、行评论、路径复制。
- 终端：显示 / 收起、输入、清理、重启、展开 / 返回会话和停靠方式的演示入口；不再使用「独立标签」文案。
- 定时任务：列表、新建、编辑、暂停 / 启用、删除、关联会话。
- 设置：服务商、权限、通用、H5、终端、MCP、Agents、Skills、记忆、插件、Computer Use、活动、诊断、关于。

主要源码定位：`desktop/src/components/layout/Sidebar.tsx`、`AppShell.tsx`、`TabBar.tsx`、`ContentRouter.tsx`；聊天区的 `ChatInput.tsx`、`MessageList.tsx`、`ActiveSession.tsx`、`WorkspacePanel.tsx` 等组件。文件可能随重构迁移，不能只凭旧文件名认定入口仍有效。

明确排除或纠正：

- 不把项目隐藏 / 恢复称为「归档」，不凭设计图新增真实归档能力。
- 文件预览不等于通用文件编辑器。
- 演示终端不执行系统命令，文件差异、任务成功、类型检查通过等是模拟内容。
- 样稿覆盖主要入口和典型状态，不等于已完整复现所有设置页及真实业务流程。
- 移除项目行的菜单后，没有保留该行「在文件管理器打开」的重复入口；当前项目仍可从聊天顶部外部应用菜单访问。是否需要为其他项目保留直接打开方式，待确认。

## 验证与未完成项

历史样稿检查：桌面与 360px 窄屏、输入自增高及无内层焦点框、权限选择、模型推理强度子菜单、文件 / 终端面板、设置和定时任务的部分演示交互。曾修复子菜单立即关闭、切换设置后终端残留等问题。这些检查针对演示 HTML，不是正式应用测试。

上一轮「菜单收敛」修改：脚本语法检查通过，两处项目菜单已从源片段移除，独立预览已同步。浏览器工具阻止读取 `file://` 页面，因此该轮未完成浏览器视觉复查，不能沿用前一版的检查结果宣称新版已全部通过。

上一轮「导航与密度」修改：移除顶部标签元素、标签状态及其事件处理；项目行常驻 plus；四权限英文展示仍兼容此前保存的中文模式状态；单行会话保留完整标题提示及触摸点击区域。脚本语法、残留引用和文件同步检查通过。此次仍未执行浏览器视觉与真实交互检查，不能据此认定新布局已验收。

上一轮「会话行一体化」修改：统一整行 hover / 选中背景，覆盖子按钮默认 hover 填色，并保持菜单展开时所属行高亮。仅修改样稿 CSS；静态结构、脚本语法及副本一致性检查通过。未进行浏览器视觉复查（本地 file:// 访问仍受工具策略限制）。

上一轮「项目行一体化」修改：仅调整项目行 CSS，让展开按钮和加号共享整行 hover / 聚焦背景。静态检查及两处样稿副本一致性检查通过；仍未进行浏览器视觉复查。

上一轮「隐藏会话时间」修改：删除列表和搜索中的时间展示，时间只作为排序字段；静态语法及副本同步检查通过，未做浏览器视觉复查。样例时间为演示数据。

最新「菜单点击修复」：新增 `checks/menu-events.cjs`，读取样稿真实点击处理代码，模拟图标被替换后事件继续冒泡。修复前断言失败，修复后按钮点击、图标替换、再次点击关闭、外部点击关闭四种情况通过。扩大点击区域并限制拖动起点；该隔离测试不能替代实际浏览器的命中区域和视觉验收。未启动临时服务或留下调试插桩。
