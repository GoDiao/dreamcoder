# 术语表

DreamCoder 服务端和桌面端代码里反复出现的领域概念。命名代码和讨论设计时用这里的词。

## 模型服务

**服务商（Provider）**：
用户在设置里保存的一份模型服务配置，包含地址、密钥、接口格式、鉴权策略和模型映射。
_避免_：渠道、供应商、API 配置

**上游（Upstream）**：
DreamCoder 服务端代替 CLI 或自己发请求时，实际接收请求的那个服务商端点。
_避免_：后端、远端、目标服务器

**接口格式（API format）**：
上游接受的请求协议，取值为 `anthropic`、`openai_chat`、`openai_responses` 之一。
_避免_：协议类型、API 类型

**鉴权策略（Auth strategy）**：
Anthropic 格式的上游如何携带密钥，决定发送 `x-api-key`、`Authorization: Bearer` 还是两者都发。
_避免_：认证方式、key 模式

**官方渠道（Official provider）**：
用 OAuth 账号登录的内置服务商（如 ChatGPT 官方），由 CLI 自己发请求，不经过上游模块。
_避免_：OAuth 服务商、官方 Provider

**基础地址（Base URL）**：
服务商配置里的地址，不含 `/v1` 和具体路径；末尾的 `/v1` 会被规范化去掉。
_避免_：endpoint、API 地址

## 关系

- 一个**服务商**有且只有一种**接口格式**；**鉴权策略**只对 `anthropic` 格式生效，OpenAI 两种格式固定用 Bearer。
- **上游**由**服务商**解析得到：**基础地址** + 接口格式对应的路径。
- **官方渠道**是**服务商**的特例，不产生**上游**。

## 示例对话

> **开发：** "用户填了 `https://openrouter.ai/api/v1`，**上游**地址会变成 `/v1/v1/chat/completions` 吗？"
> **维护者：** "不会。**基础地址**统一去掉末尾的 `/v1`，**上游**模块再按**接口格式**拼路径。"
> **开发：** "那 ChatGPT 官方呢？"
> **维护者：** "那是**官方渠道**，CLI 自己发请求，不走**上游**模块。"

## 已澄清的歧义

- "代理（proxy）"同时指用户的网络代理和 `/proxy` 格式转换接口。结论：网络代理叫"网络代理"，`/proxy` 接口叫"格式转换代理"；两者都不是**上游**。
